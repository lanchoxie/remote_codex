# v2.4.11

Release date: 2026-08-07

`v2.4.11` is a production hotfix for Session error reporting, stale lifecycle
state, and recoverable Thinking history. The source was accepted on the isolated
8897 Relay and promoted to the 8797 production Relay before this release.

## Fixed

- Restored older persisted Thinking entries when the user explicitly loads older
  transcript messages. The browser fetches full diagnostics once per Session,
  while retaining bounded caches and DOM limits for long-running mobile pages.
- Replaced the generic `Codex thread entered a system error state` alert with the
  later concrete Codex error for the same Turn, such as `serverOverloaded`,
  instead of showing both messages.
- Preserved Turn and client-request correlation while refining provisional
  system errors, and fenced late errors so an old Turn cannot overwrite a newer
  active Turn.
- Prevented reverse event order from downgrading an already concrete Codex error
  back to the generic `systemError` state.
- Made `session.started` authoritative for a new run. A newly created Session or
  API switch no longer inherits stale `stopping`, busy, queue, approval, or
  active-Turn state from the previous run.
- Broadcast a complete runtime projection after `session.started`, keeping Relay
  state and the mobile UI aligned immediately after Start, Resume, or Rebind.

## Regression Coverage

- Added Host Runner tests for provisional-to-concrete error refinement, old-Turn
  fencing, reverse event order, and bounded terminal-error context.
- Added Relay and UI tests for replacing provisional alerts and preserving
  concrete Codex error metadata.
- Added UI cache-budget coverage for evicting and reloading full Thinking
  diagnostics.
- Re-ran the focused Session API, managed Session, local-history, transcript, and
  rendering-performance suites before promotion.

## Production Validation

- The accepted Runner, Relay, and mobile UI source files were hash-verified
  between 8897 and 8797.
- The restarted 8797 Relay reported ready with writable persistence, and all five
  configured production Hosts were online.
- The local `illuin` Host Agent was restarted on the new Runner source. Remote
  Host Agents with live managed Sessions were not force-restarted; their
  Host-side Runner fix takes effect after their next controlled update or
  restart. Relay and UI fixes are already active on 8797.

Runtime state, Session data, logs, credentials, API keys, downloaded caches, and
machine-local configuration are not included in this source release.
