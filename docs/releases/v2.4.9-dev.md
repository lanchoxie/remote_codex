# v2.4.9-dev Development Candidate

Release date: 2026-07-28

`v2.4.9-dev` is a source-only development candidate based on `v2.4.8`. It packages
the accepted 8897 repair work for a controlled 8797 production test. It is a
pre-release tag and is intentionally excluded from the application's stable-tag
selection.

## Highlights

- Made prompt delivery recoverable across Relay restarts with a durable input outbox,
  request-ID-scoped pending/accepted/rejected transcript projection, canonical scope
  migration, and late-echo suppression.
- Made runtime state monotonic across Runner, Host Agent, Relay, and browser. Busy
  rejections no longer replace the active turn, and Stop/Interrupt remain correlated
  with the exact run, turn, and client request until Host settlement.
- Hardened legacy null/unknown API Sessions with capability-gated Rebind, exactly-once
  first input, and complete draft/attachment restoration on cancellation or rejection.
- Expanded Thinking into structured, collapsible command, tool, file-change, and
  parent/subagent collaboration details while preserving disclosure, scroll, focus,
  and detached-reader viewport state.
- Refined Approval into a compact, non-disruptive popup with expandable request details,
  duplicate-response locking, light-theme support, and only Codex-advertised decisions.
- Hardened local Host recovery against stale ownership markers and PID reuse without
  killing unrelated processes, while retaining adoption of a genuine previous Agent.
- Fixed Host Codex maintenance remaining stuck at `updated` when no Sessions need
  recovery, and condensed software-update details to package/version/tag information.
- Made managed Codex overlay cleanup resilient to Windows `EBUSY` locks with bounded
  retries and nonterminal warnings while preserving the original startup error.

## Session Input and Runtime State

- Relay assigns a stable `clientRequestId` to legacy clients and persists a provisional
  user message before Host acceptance is known.
- The input outbox durably records the command and a secret-free transcript projection,
  checkpoints accepted/rejected outcomes, and replays unfinished projection work after
  restart.
- Rejected optimistic messages are removed by request identity and tombstoned so later
  SSE, detail, or native transcript echoes cannot resurrect them.
- Canonical Session migration durably moves outbox scope before in-memory aliases and
  reservations, preventing a restart/retry from issuing the same command twice.
- Submission rechecks runtime ownership and revision after asynchronous model/profile
  preparation, closing the race where another turn becomes active before WAL enqueue.
- `runtimeRevision`, run identity, active client identity, and command acknowledgement
  identity are kept distinct across Runner, Agent, Relay, and browser.
- Interrupt supports acceptance-unknown starts and stays locked until the exact native
  turn settles; duplicate Interrupt actions are idempotent.
- Per-Session drafts now retain editable text, attachments, browser `File` objects,
  sent snapshots, active submissions, selections, and local image paths across Session
  changes, API switching, Rebind cancellation, and definitive rejection.
- `cursor_missing` and canonical-key changes force authoritative detail recovery rather
  than merging rejected optimistic state back into history.

## API, Rebind, and Host Management

- Legacy null/unknown bindings cannot use ordinary Resume; explicit Rebind selects a
  compatible Host profile or Host environment and sends the original first input once.
- Rebind capability gates fail closed on older Agents before catalog, plan, Stop, or
  Start operations.
- Host Codex probe/update reports installation source, version, platform, architecture,
  optional package, and auto-update eligibility. Only recognized npm-global installs
  are automatically updated.
- A no-recovery Host update now reaches a terminal maintenance result so later API
  switching is not incorrectly blocked. Updates with Sessions to restore remain in
  maintenance until recovery completes.
- The software-update detail surface now shows only package path, current version,
  current tag, and latest stable tag; updater safety checks still detect tracked changes
  and leave untracked files alone.

## Thinking, Approval, and Internal Tasks

- Command input, arguments, output, result, file diffs, and truncation notices are
  independently expandable instead of being clipped into one flat row.
- Parent/subagent sender, recipients, prompt, status, and result metadata are shown in
  the parent Thinking stream when Codex supplies plaintext fields. Encrypted payloads
  display an explicit unavailable marker and are not locally decrypted.
- Guardian Approval and ordinary child rollouts are hidden from normal writable Session
  lists; direct input to a child rollout is rejected while available collaboration
  activity remains visible in the parent.
- Approval requests no longer force the Session details surface open. Detailed command,
  file, permission, and amendment data is behind disclosures, and repeated responses
  are locked.

## Local Agent and Windows Cleanup

- Local ownership probing records process start time, executable, command line, and
  Agent entrypoint, and assesses markers as stale, PID-reused, live, or unknown.
- Stale/PID-reused marker deletion revalidates PID, instance ID, and token immediately
  before removal. Unknown identity remains fail-closed, and a PID from the marker is
  never killed merely because it was recorded there.
- A live previous Agent can still register with its matching token and be adopted after
  Relay restart without creating a duplicate Agent.
- Managed overlay removal retries transient Windows locks five times with a 100 ms
  delay, then uses bounded background retries. Cleanup warnings do not alter stopped or
  history-only state and do not replace a primary startup error.

## Known Limitations

- Goal persistence is not part of this release. `goals_1.sqlite` remains inside the
  disposable per-managed-run overlay, so successful cleanup can remove Goal objective,
  status, budget, usage, elapsed-time, and continuation-deferral state even though
  shared Session rollout history survives. This is the next 8897-only persistence task.
- Real provider legacy Rebind, remote model listing, multi-Host batch Apply, full pi5
  Codex stop/update/resume, and long mobile/heap behavior still require controlled
  environment acceptance.
- Encrypted collaboration payloads cannot be decrypted by Relay or browser.
- The condensed software-update summary lacks a dedicated UI regression.
- HTTP Range resume and a dedicated browser mid-download-abort integration test are not
  implemented.
- A genuine Session Store WAL revision gap remains fail-closed.

## Packaging Boundary

This tag contains source and tests only. It excludes `tmp`, SQLite/WAL files, Session
Store state, logs, ownership markers, PID/lock files, authentication/account data,
Connector secrets, API keys, downloaded runtimes, received-file caches, `CODEX_HOME`,
`node_modules`, exported Sessions, generated backups, and machine-local configuration.

No native runtime assets are published for this pre-release, so
`runtimeReleaseTag`/runtime download defaults remain pinned to the existing `v2.4.8`
asset release. See `docs/8897-session-state-sync-handoff-2026-07-27.md` for the full
historical issue ledger, evidence map, acceptance checklist, and unresolved boundaries.
