# v2.4.9

Release date: 2026-08-05

`v2.4.9` is the stable release of the accepted `v2.4.9-dev` production
candidate plus the lifecycle, realtime transcript, Thinking, and mobile fixes
validated on the 8797 production Relay.

## Highlights

- Made prompt submission and optimistic transcript projection recoverable across
  retries and Relay restarts without duplicate user messages.
- Made Session runtime state monotonic across Runner, Host Agent, Relay, and
  browser, including correlated Stop, Interrupt, queue, and active-turn state.
- Fixed failed Resume and Rebind launches remaining permanently stuck in
  `starting` or `busy`, which caused false `Session became active after preflight`
  and `Cannot Resume` errors.
- Restored structured Thinking history so commentary messages, tool calls,
  command output, file changes, and parent/subagent activity remain visible as
  stable log entries instead of being overwritten by the latest snapshot.
- Improved realtime terminal and transcript synchronization, late activity
  recovery, discovery batching, and large-history rendering performance.
- Improved mobile rendering for wide Markdown tables and compact Session action
  controls, added `Copy Dir` beside `Copy ID`, and retained stable transcript
  scroll position.
- Hardened Session persistence, atomic replacement, notification identity,
  Connector path normalization, and Codex rollout tailing.

## Session Lifecycle Recovery

- Host startup failures now emit a terminal Session event even when a retained
  Runner is kept for retry diagnostics.
- Relay discovery can reclaim a pending managed Start that is no longer present
  in an authoritative Host snapshot, including `starting + live=false` records.
- Relay restart reconciliation fails unconfirmed pending runs, clears the active
  run pointer, restores the last successful run, and preserves the complete
  transcript.
- Parent-run events can no longer incorrectly settle a newer pending child run.
- Retry and idempotency handling remain scoped to the original client request and
  run identity.

## Thinking And Realtime UI

- Thinking activities now carry an immutable `startedAt` and a revision
  `timestamp`, keeping late final snapshots attached to the correct turn.
- Projected commentary reads the canonical top-level text field and is no longer
  dropped while tool calls remain visible.
- Revision replacement preserves the original activity start time and avoids
  duplicate command/output rendering.
- Session watch batching and incremental discovery reduce unnecessary full
  history work during long-running browser sessions.

## Verification

- The full focused Session API unit and integration suites passed on the isolated
  8897 development Relay.
- Transcript, notification, realtime synchronization, managed Session, lifecycle,
  and Windows startup regression suites passed before production promotion.
- The accepted source was promoted to 8797 and restarted with writable Session
  persistence.
- All five production Hosts reconnected. The previously stuck dm Resume run was
  closed without deleting its 235 transcript entries, and the local illuin
  Session retained all 35 entries.

These are the previously published, hash-verified runtime payloads. The installer

## Known Limitations

- Remote Host Agents must be restarted or updated before they gain the Host-side
  startup-failure reporting fix. Relay-side stale pending-run recovery is active
  immediately after the Relay update.
- A very large existing Session Store can take longer than the Windows launcher's
  current health wait window. The Relay may continue initializing successfully
  after the launcher reports a timeout.
- Goal persistence remains outside the shared managed Session history store.
- Runtime state, Session data, logs, credentials, Connector secrets, API keys,
  downloaded caches, and machine-local configuration are not included in source
  tags or archives.
